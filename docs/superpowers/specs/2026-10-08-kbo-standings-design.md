# KBO 전체 순위

## 목적과 범위

경기 일정을 보다가 앱 안에서 현재 시즌 KBO 정규리그 전체 순위를 확인한다.
가입 때 선택한 응원 구단을 그대로 사용하며, 구단 선택이나 미설정 안내를 추가하지 않는다.
홈·캘린더·프로필과 같은 글꼴, 색상, 여백, 공통 컴포넌트를 사용한다.

첫 버전은 현재 시즌의 최신 공식 순위만 제공한다. 과거 시즌 선택, 순위 변동 그래프,
선수 순위, 실시간 경기 점수와 포스트시즌 순위는 범위에 포함하지 않는다.

## 기존 화면 확인

- iPhone 17 Pro / iOS 26.5 시뮬레이터에서 홈, 캘린더, 프로필을 직접 확인했다.
- 글꼴은 `src/styles/fonts.ts`의 Pretendard를 사용한다.
- 배경, 본문, 보조 문구, 포인트 색은 `src/styles/colors.ts`를 사용한다.
- 캘린더는 연회색 바탕 위 흰색 달력, 가운데 제목, 좌우 20pt 여백을 사용한다.
- 공통 `AppBottomSheet`는 흰색 바탕, 24pt 안쪽 여백, 제목과 닫기 버튼을 제공한다.
- `kill-ai-slop` 스캔은 160개 파일에서 24개 후보를 찾았다. 완료 취소선, 사용자 편집 서식,
  티켓북 표지의 SVG, 소스 주석에 해당하므로 이번 작업에서 변경하지 않는다.

## 화면과 동작

### 진입

캘린더 상단의 가운데 제목은 유지하고 오른쪽에 `순위` 보조 버튼을 추가한다.
`프로필 수정`과 공통 `SecondaryButton`을 사용한다. 최소 높이 44pt, 모서리 8pt,
글자 13pt, 테두리 1pt와 기존 색상·글꼴 토큰을 공유한다. 하단 탭은 그대로 사용한다.
조회되는 순위는 캘린더에서 선택한 날짜와 무관한 현재 시즌 최신 순위다.

### 순위표

바텀시트를 사용하지 않는다. 캘린더 위에 페이드로 열리는 넓은 중앙 모달을 사용한다.
작은 화면이나 큰 글자 설정에서는 전체 화면으로 넓히고, `AppText`와 기존 색상 토큰을 재사용한다.
제목은 `KBO 순위`, 보조 문구는 `2026 정규시즌`과 같은 실제 시즌 정보로 표시한다.
기준일은 화면에 표시하지 않고 내부 데이터 검증에 사용한다.

표의 열은 `순위 / 구단 / 승 / 패 / 무 / 승률 / 게임차`로 고정한다.
구단은 기존 단축 이름을 사용하고 숫자는 오른쪽 정렬 및 동일 폭 숫자로 맞춘다.
10개 구단을 공식 순위 순서대로 모두 표시한다. 동률 순위는 원문 값을 유지한다.
각 행은 기본 44pt 이상으로 하고 글자가 커지면 행 높이가 늘어날 수 있게 한다.
작은 기기에서는 표 내부를 세로로 스크롤할 수 있다. 큰 글자 설정에서 폭이 부족하면
표만 가로 스크롤하고 숫자나 구단명을 생략하지 않는다.

응원 구단 행에만 기존 `primary50` 배경과 굵은 구단명을 적용한다.
스크린리더의 행 설명에 `응원 구단`을 포함해 색상에만 의존하지 않는다.
각 행을 구단, 순위, 승패무, 승률, 게임차 순서로 읽을 수 있게 한다.
표에는 얇은 가로 구분선을 사용하며, 구단별 카드나 별도 요약 카드를 추가하지 않는다.
모달에는 출처 문구나 외부 링크를 표시하지 않는다. 저장된 순위의 재조회를 위한 새로고침만 제공한다.

### 조회 상태

- 처음 불러올 때: 표 영역에 공통 스켈레톤과 로딩 접근성 설명을 표시한다.
- 저장된 순위가 없을 때: `아직 순위가 집계되지 않았어요`를 표시한다. 순위를 만들지 않는다.
- 첫 조회 실패: 간결한 실패 문구와 `다시 시도` 버튼을 표시한다.
- 이전 데이터가 있는 상태에서 재조회 실패: 이전 표를 유지하고 갱신 실패를 알린다.
- 승패로 계산할 수 없는 승률은 `집계 전`으로 표시한다.
- 닫기 버튼, 중앙 모달 바깥 영역 터치, Android 뒤로가기로 닫는다.

## 데이터 흐름

KBO 공식 일자별 팀 순위를 기존 Playwright 수집기로 읽고 Supabase에 저장한다.
원문 순위, 승패무, 승률, 게임차를 사용하며 기존 경기 결과로 재계산하지 않는다.
경기 수 차이로 생기는 음수 게임차도 원문대로 보존한다.
출처: https://www.koreabaseball.com/Record/TeamRank/TeamRankDaily.aspx

시즌별 최신 스냅샷 한 건에 공식 기준일, 10개 구단의 순위 데이터와 수집 시각을 저장한다.
구단 ID는 기존 `teams` ID에 매핑한다. 현재 시즌과 기준일, 알려진 10개 구단의 중복 없는
목록, 수치 범위를 검증한 뒤 한 번에 교체한다. 불완전한 수집은 이전 데이터를 보존하고 실패한다.
새 migration에 스냅샷 테이블과 RLS를 추가한다. 로그인 사용자는 조회만 가능하고
기존 서버 수집기만 저장할 수 있다. 관리자 키는 앱으로 전달하지 않는다.

당일 상태 수집과 전날 보정 작업에 순위 수집을 연결하고 수동 실행도 제공한다.
앱은 `src/features/standings`의 서비스와 React Query 훅으로 현재 시즌을 조회한다.
모달을 열었을 때만 조회하고, 캐시 유효 시간은 5분으로 설정한다.
새 의존성은 추가하지 않는다.

## 구현과 검증 대상

- 캘린더 진입 버튼, 순위 모달과 관련 행동 테스트
- 순위 타입, 서비스, 조회 훅과 경계 데이터 검증 테스트
- 공식 순위 수집·검증·저장과 누락·중복 구단 회귀 테스트
- Supabase migration, 앱 DB 타입, 스냅샷 읽기·쓰기 권한 테스트
- 기존 수집 workflow의 순위 수집 연결
- 관련 Jest 테스트 → `npm run verify`, `npm run verify:db`
- 실제 시뮬레이터에서 변경 전후 화면, 열 정렬, 응원 구단 강조, 스크롤과 닫기 확인

운영 반영에는 migration 적용과 수집 workflow 배포, 최초 순위 수집이 필요하다.
로컬 검증과 운영 데이터 반영 결과를 구분해서 보고한다.
